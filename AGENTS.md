# tide

tide, a self-hosted media server on one Ubuntu host, LAN only, in Docker Compose: Seerr takes the requests, Radarr (movies) and Sonarr (shows) search them through Prowlarr, download them with qBittorrent and import them into the library, Bazarr gets their subtitles, and Jellyfin plays them. `tide/` holds `tide wire`, a Python command that wires those services together through their APIs. `README.md` describes the setup.

The host keeps the library in `~/Media/{movies,shows,music}` and the downloads in `~/Media/downloads`, on the same disk. qBittorrent, Radarr, Sonarr and Bazarr mount `~/Media` at `/data`, so a download has the same path in all of them and an import is an instant rename; Jellyfin mounts it at `/media`. Every service joins the external Docker network `tide` (`docker network create tide`) and reaches the others by container name. Music is managed by hand. `~/Media/Discover` holds only the placeholders of the JellyBridge plugin, which Seerr must not scan and no *arr uses.

## Map

| Path | Holds |
|---|---|
| `jellyfin/` | `docker-compose.yml`: `jellyfin/jellyfin:latest` as `1000:1000`, ports `8096/tcp` (web UI and API), `7359/udp` and `1900/udp` (discovery), the named volumes `jellyfin-config` and `jellyfin-cache`, `MEDIA_DIR` mounted read-write at `/media`, a health check on `/health` and caps of `JELLYFIN_CPUS` (4) and `JELLYFIN_MEMORY` (3G), since the host also runs other workloads. `.env.example` lists the variables. `README.md` covers the commands, the library setup, the library `Discover` of the JellyBridge plugin (Seerr's catalog as placeholders in `~/Media/Discover`, a favorite sent to Seerr as a request; `make wire` sets it up, all but installing the plugin and picking what it shows) and transcoding, and `SUBTITLES.md` where the subtitles come from: the tracks a video file already carries, Bazarr with OpenSubtitles.com or an `.srt` saved by hand, since no subtitle plugin is installed. |
| `qbittorrent/` | `docker-compose.yml`: `lscr.io/linuxserver/qbittorrent:latest` as `1000:1000`, the web UI on `WEBUI_PORT` (8080), the peer port `6881` tcp and udp, the named volume `qbittorrent-config`, `MEDIA_DIR` mounted at `/data` and caps of `QBIT_CPUS` (2) and `QBIT_MEMORY` (2G). `.env.example` lists the variables. `README.md` covers the settings Radarr and Sonarr need: the save path `/data/downloads`, unfinished torrents in `/data/downloads/incomplete`, and stopping (not removing) each torrent at ratio `0`, since they remove it after the import. |
| `prowlarr/` | `docker-compose.yml`: `lscr.io/linuxserver/prowlarr:latest` as `1000:1000`, the web UI on `9696`, the named volume `prowlarr-config`, a health check on `/ping` and caps of `PROWLARR_CPUS` (1) and `PROWLARR_MEMORY` (512M). `README.md` covers the indexers, with the Internet Archive as the example, the indexer proxy FlareSolverr for those behind Cloudflare (the tag `flaresolverr`) and their sync to Radarr and Sonarr. |
| `flaresolverr/` | `docker-compose.yml`: `ghcr.io/flaresolverr/flaresolverr:latest`, whose image runs as `flaresolverr` (`1000:1000`), no published port (Prowlarr calls it at `http://flaresolverr:8191`), no volume, `LOG_LEVEL` (`info`), a health check on `/health` and caps of `FLARESOLVERR_CPUS` (1) and `FLARESOLVERR_MEMORY` (1G), for its headless Chromium. `.env.example` lists the variables. `README.md` covers what it is for, that passing a site's challenge can breach that site's terms of use, the commands and the new image that fixes it when Cloudflare changes its challenge. |
| `radarr/` | `docker-compose.yml`: `lscr.io/linuxserver/radarr:latest` as `1000:1000`, the web UI on `7878`, the named volume `radarr-config`, `MEDIA_DIR` mounted at `/data`, a health check on `/ping` and caps of `RADARR_CPUS` (1) and `RADARR_MEMORY` (1G). `README.md` covers the naming, the root folder `/data/movies`, qBittorrent with the category `radarr`, the Jellyfin connection, the custom format `Portuguese (Brazil)` and the Library Import. |
| `sonarr/` | `docker-compose.yml`: `lscr.io/linuxserver/sonarr:latest` as `1000:1000`, the web UI on `8989`, the named volume `sonarr-config`, `MEDIA_DIR` mounted at `/data`, a health check on `/ping` and caps of `SONARR_CPUS` (1) and `SONARR_MEMORY` (1G). `README.md` covers the same setup as Radarr, with the root folder `/data/shows` and the category `sonarr`. |
| `seerr/` | `docker-compose.yml`: `seerr/seerr:latest` (formerly Jellyseerr), whose image runs as `node` (`1000:1000`), the web UI on `5055`, the named volume `seerr-config` at `/app/config`, a health check on `/api/v1/status` and caps of `SEERR_CPUS` (1) and `SEERR_MEMORY` (1G). `README.md` covers its setup with Jellyfin, Radarr and Sonarr, and the libraries it scans: every one but `Discover`. |
| `bazarr/` | `docker-compose.yml`: `lscr.io/linuxserver/bazarr:latest` as `1000:1000`, the web UI on `6767`, the named volume `bazarr-config`, `MEDIA_DIR` mounted at `/data`, a health check on `/api/system/ping` and caps of `BAZARR_CPUS` (1) and `BAZARR_MEMORY` (1G). `README.md` covers the language profile `Portuguese (Brazil)`, the provider OpenSubtitles.com and the connections to Radarr and Sonarr. |
| `tide/src/tide/main.py` | The entry point (`tide wire` runs `run()`, argparse with the one subcommand `wire`): `EnvironmentService.from_env()` reads the configuration and `build_wire_command` builds a `KeyService`, an `ApiClient` per service (`/api/v3` for Radarr and Sonarr, `/api/v1` for Prowlarr and Seerr, timeout 30 seconds, `id_in_body` true for the *arr apps, `media_browser` true only for Jellyfin), two `ArrService` (Radarr: `/data/movies`, `movieCategory` `radarr`, the movie naming; Sonarr: `/data/shows`, `tvCategory` `sonarr`, the show naming), `ProwlarrService`, `SeerrService`, `BazarrService` (`/api`, `id_in_body` false) and `JellyfinService` (no base path, the key `TIDE_JELLYFIN_API_KEY`), injects them into `WireService` and that into `WireCommand`, whose `execute()` is the exit code. It only wires. |
| `tide/src/tide/application/cli/` | One command per file. `WireCommand` (`wire_command.py`) receives a `Wire` and runs it once: it prints `done   <step>` for each step done, `failed <step>: <reason>` for each that failed, and the summary `wire: N done, N failed`. It returns `1` when a step failed, `0` otherwise. |
| `tide/src/tide/core/domain/` | The data that crosses the layers, one dataclass per file. `WireReport`: what one wire did, the `done` steps and the `failed` ones. `Failure` (frozen): a step and the reason it failed. |
| `tide/src/tide/core/interfaces/` | One `Protocol` per file. `MediaManager` (Radarr, Sonarr: `add_root_folder()`, `name_files()`, `prefer_portuguese()`, `use_qbittorrent()`, `notify_jellyfin()`, `import_subtitles()`), `IndexerManager` (Prowlarr: `sync(app)`), `RequestManager` (Seerr: `send_to_radarr()`, `send_to_sonarr()`, `skip_discover()`), `SubtitleManager` (Bazarr: `prefer_portuguese()`, `use_providers()`, `follow(app)`), `MediaServer` (Jellyfin: `add_repository()`, `bridge_seerr()`, `add_discover()`) and `Wire` (`run()`). |
| `tide/src/tide/core/services/` | `WireService` (`wire_service.py`), which receives the two media managers, the indexer manager, the request manager, the subtitle manager and the media server. Its `run()` does the steps in order, each labelled `<service>: <what>`: the six of Radarr (`root folder`, `naming`, `Portuguese (Brazil)`, `qBittorrent`, `Jellyfin`, `subtitles`), the same six of Sonarr, `prowlarr: radarr`, `prowlarr: sonarr`, `seerr: radarr`, `seerr: sonarr`, `jellyfin: repository`, `jellyfin: JellyBridge`, `jellyfin: Discover`, `seerr: libraries`, `bazarr: Portuguese (Brazil)`, `bazarr: providers`, `bazarr: radarr` and `bazarr: sonarr`. An `OSError` of a step is a `Failure` and the next step still runs. |
| `tide/src/tide/infrastructure/http/` | `ApiClient` (`api_client.py`): `get`, `post` and `put` of JSON to `<url><path>`, and `post_form` of a form (a list field repeated once per value) whose answer is ignored, as Bazarr takes its settings, with the API key from its `key` callable, asked on each call, in the header `X-Api-Key` or, with `media_browser`, as `Authorization: MediaBrowser Token="<key>"`, the only form Jellyfin takes, and the timeout; an empty answer, such as Jellyfin's `204`, is `None`, and an HTTP error becomes an `OSError` `<METHOD> <path>: HTTP <code> <body of the answer>`. `upsert(path, body)` puts over the item under `path` with the body's `name`, or posts it, and answers the item as saved; with `id_in_body` the put carries the item's `id` too, which the *arr APIs want and Seerr rejects as read-only. `schema.py`: `find(items, field, value)`, an `OSError` `no <field> <value>` when none matches, and `with_values(fields, values)`, which sets the `value` of the `{name, value}` fields of an *arr schema by name. |
| `tide/src/tide/infrastructure/arr/` | `ArrService`, the `MediaManager` of Radarr or Sonarr, which share their API v3, given the root folder, the naming, the qBittorrent category field and category, the quality profile, the qBittorrent login and the Jellyfin key. `add_root_folder()` posts the root folder unless it is there; `name_files()` puts the naming over the current one; `prefer_portuguese()` finds the id of `Portuguese (Brazil)` in `/language`, since Radarr and Sonarr number their languages differently, upserts the custom format `Portuguese (Brazil)` (a required `LanguageSpecification` of that id) and scores it `100` in the quality profile; `use_qbittorrent()` upserts the `QBittorrent` schema as `qBittorrent` at `qbittorrent:8080` with the category and Remove Completed and Remove Failed on; `notify_jellyfin()` upserts the `MediaBrowser` schema as `Jellyfin` at `jellyfin:8096`, Update Library on every `on…` event that matches `Download`, `Upgrade`, `Rename` or `…Delete`, `/data/` mapped to `/media/`; `import_subtitles()` puts Import Extra Files on, with the extension `srt`, over the media management. |
| `tide/src/tide/infrastructure/prowlarr/` | `ProwlarrService`, the `IndexerManager`, given a `key_of(container)`: `sync(app)` upserts the `Radarr` or `Sonarr` application schema with Full Sync, `prowlarrUrl` `http://prowlarr:9696`, the app's `baseUrl` (`http://radarr:7878`, `http://sonarr:8989`) and its API key. |
| `tide/src/tide/infrastructure/seerr/` | `SeerrService`, the `RequestManager`, given a `key_of(container)`, the quality profile and the LAN host. It posts the connection (`hostname` the container name, `port`, `apiKey`) to `/settings/<app>/test`, takes the id of the quality profile from its answer and upserts `/settings/<app>` as the default server with the root folder and `externalUrl` `http://<lan host>:<port>`; Radarr with `minimumAvailability` `released`, Sonarr with the same profile and folder for anime and season folders. `skip_discover()` posts `/settings/jellyfin/library/sync`, which answers the libraries Jellyfin has, and puts `enabled` on each by id, false only for the one named `Discover`, whose placeholders Seerr would take as available. |
| `tide/src/tide/infrastructure/bazarr/` | `BazarrService`, the `SubtitleManager`, given a `key_of(container)` and the OpenSubtitles.com login, each `None` when not set. Every step posts a form to `/system/settings`, which replaces the languages, the profiles and the providers whole, so each sends what Bazarr has with tide's added. `prefer_portuguese()` upserts the language profile `Portuguese (Brazil)` (language `pb`) by name, with the id it had or the next one, keeps the other profiles and enabled languages, enables `pb` and makes the profile the default of the movies and the series; `use_providers()` adds `opensubtitlescom`, with its username and password, to the enabled providers when both are set, and sends nothing when either is missing; `follow(app)` turns on Radarr or Sonarr at its container name and port with its API key and base URL `/`. |
| `tide/src/tide/infrastructure/jellyfin/` | `JellyfinService`, the `MediaServer`, given a `key_of(container)`. Jellyfin replaces its repositories and a plugin's settings whole, so each step sends what Jellyfin has with tide's changed. `add_repository()` posts the repositories with `Jelly Bridge` (JellyBridge's `manifest.json` on GitHub) replaced or added by name; `bridge_seerr()` finds the plugin `JellyBridge` in `/Plugins` (an `OSError` `no Name JellyBridge` when it is not installed) and posts its configuration back with `JellyseerrUrl` `http://seerr:5055`, Seerr's `ApiKey`, `LibraryDirectory` `/media/Discover`, `IsEnabled` true and `UserPermissionRequest4k` false (on, an admin's favorite is a 4K request, and Seerr has no 4K server) and `EnableStartupSync` true (the sync task's 24-hour interval restarts with Jellyfin, which the host, shut down every day, never keeps up that long), what it shows and the rest as they were; `add_discover()` posts the library `Discover` (`mixed`, on `/media/Discover`, refreshed) unless one has that name. Installing the plugin, which restarts Jellyfin, is left to a person. |
| `tide/src/tide/infrastructure/docker/` | `KeyService`, given the keys from the environment and the `docker` command: `key(container)` answers the given key or reads it with `docker exec <container> cat`, from `/config/config.xml` (`ApiKey`) for an *arr, `/app/config/settings.json` (`main.apiKey`) for Seerr and `/config/config/config.yaml` (the `apikey` of its `auth` block) for Bazarr. A failed `docker exec` is an `OSError` with what docker said on stderr, and a config without the key an `OSError` too. |
| `tide/src/tide/infrastructure/environment/` | `EnvironmentService` (frozen dataclass), whose `from_env(environ)` reads `TIDE_QBIT_PASSWORD`, `TIDE_JELLYFIN_API_KEY` and `TIDE_LAN_HOST`, required; `TIDE_QBIT_USERNAME` (`admin`) and `TIDE_QUALITY_PROFILE` (`HD-1080p`); `TIDE_RADARR_URL`, `TIDE_SONARR_URL`, `TIDE_PROWLARR_URL`, `TIDE_SEERR_URL`, `TIDE_BAZARR_URL` and `TIDE_JELLYFIN_URL`, `http://localhost:<published port>` by default; `TIDE_<SERVICE>_API_KEY`, and `TIDE_OPENSUBTITLES_USERNAME` and `TIDE_OPENSUBTITLES_PASSWORD`, `None` when empty. A missing required variable prints `<NAME> is not set (see tide/.env.example)` to stderr and exits with code `2`. `tide/.env.example` lists the variables and why each is needed. |
| `tide/tests/` | `unit/` mirrors `src/tide/`, one test file per service or command. `integration/` has one file per command (`test_wire_command.py`): each test starts a `FakeServer` per service, answering like a fresh Radarr, Sonarr, Prowlarr, Seerr and Bazarr and a fresh Jellyfin with JellyBridge installed, runs the real `tide wire`, the console script next to the Python of the tests, as a subprocess with only the `TIDE_*` variables it sets (every URL and every API key, so docker is never run), and checks its exit code and output or a request a service got. `pyproject.toml` sets `--import-mode=importlib`, since `unit/` and `integration/` share file names. `mocks/http_server.py` holds `FakeServer`, a real HTTP server on localhost whose routes map `(method, path)` to a `Response`, answered after its `delay`, and which records every `Request`; `conftest.py` gives one to tests as the `fake_server` fixture and starts more with the `fake_servers` fixture. |
| `.github/workflows/` | `continuous-integration.yml` (pull requests): Build, Lint, Audit, Unit Tests and, after them, Integration Tests and Mutation Tests, each through `make`; Mutation Tests fails on a surviving mutant and writes the counts to the job summary. `continuous-deployment.yml` (on `main`): `heronlabs/action-tag-release` bumps `version.txt` from the squash commit, writes `CHANGELOG.md`, tags and publishes the release. `dependabot.yml` updates the actions, grouped, and tide's `uv.lock`. |
| `.githooks/pre-commit` | `make -C tide lint test` when staged changes touch tide's Python files, `pyproject.toml` or `uv.lock`. |

Import rules: `application` imports only `core`; `core/services` imports only `core/domain` and `core/interfaces`; `core/domain` and `core/interfaces` import only `core/domain`; `infrastructure` imports only `core/domain` and `infrastructure/http`. Only `main.py` imports `infrastructure`, and pyright checks there that each service matches the `Protocol` it is injected as.

## Commands

| Command | Does |
|---|---|
| `make wire` | `tide wire` on the host, with the variables of `tide/.env` |
| `make build` | `uv build` in `tide/`: wheel and sdist in `tide/dist/` |
| `make lint` | actionlint (with shellcheck on the workflow scripts), shellcheck on `.githooks/pre-commit`, `docker compose config` of each service with its `.env.example`, then tide's `ruff check`, `ruff format --check`, `pyright` and `uv lock --check` |
| `make lint:fix` | tide's `ruff format`, then `ruff check --fix` |
| `make audit` | pip-audit over the dependencies `tide/uv.lock` pins, hashes required |
| `make test` | tide's unit tests (`pytest tests/unit`) |
| `make test:coverage` | tide's unit tests with line and branch coverage; `main.py` is left out |
| `make test:integration` | tide's integration tests (`pytest tests/integration`): the real `tide wire` against a `FakeServer` per service |
| `make test:mutation` | mutmut over `tide/src/tide/`, `main.py` excluded, against the unit tests; fails when a mutant survives or no test reaches it. Mutants and `mutmut-cicd-stats.json` in `tide/mutants/` |

The tide targets run the target of the same name in `tide/Makefile`. `actionlint` and `shellcheck` run through `uvx`, pinned in the root `Makefile`. The target names use a colon (`test:coverage`), not a dash.

## Conventions

- **Tests:** unit tests in `tests/unit/` mirroring `src/tide/`, one file per service or command (`test_wire_service.py`); integration tests in `tests/integration/`, one file per command, only through the real `tide wire`. One `class TestGiven<Method>` per method under test (`TestGivenRun`) and one `test_should_...` per behavior. Arrange, act and assert are separated by blank lines, and each test has a single assertion; an integration test asserts the exit code and the output in one condition, or a request a service got. No `parametrize`, no loops, no unit tests for `main.py`.
- **Mutants:** every mutant is killed. A surviving mutant needs a test; an equivalent one is fixed by refactoring the code (one sort order, one way to make a POST, no dead check). Only a mutant no refactor can tell apart gets `# pragma: no mutate` on its statement, with a comment saying why: today only the case of the header names of `ApiClient`, which urllib normalizes. A JSON body is asserted whole, in one assertion, so every field of it kills its mutants. The pragma covers only a line that starts a statement.
- **Integration tests never reach the real host:** the command gets only the `TIDE_*` variables the test sets, never `os.environ`: every `TIDE_*_URL` points at a `FakeServer` and every `TIDE_*_API_KEY` is given, so it never reaches the real services nor runs docker.
- **Test data** is built inside each test, repeated when two tests need the same values. No module-level constants shared between tests. Helpers build fresh state on each call (taking `tmp_path` or a `FakeServer`) and receive their values as parameters.
- **Fakes** are written by hand at the top of the test file that uses them (`FakeMediaManager`, `FakeIndexers`, `FakeWire`) and implement the `Protocol` of the code under test. Shared helpers live in `tests/mocks/`. HTTP is the real `FakeServer`; docker is a fake `docker` script in `tmp_path`.
- **Layout:** one class per file. `core/domain` holds data only, as dataclasses, grouped by area (`library/`). `core/interfaces` holds one `Protocol` per file. Infrastructure services are `infrastructure/<area>/<name>_service.py`, and an API answer would be a data-only `<name>_response.py` in the package that reads it.
- **Dependencies** enter through constructors. Only `main.py` wires.
- **The runtime uses only the standard library.** Every dependency in `pyproject.toml` is in the `dev` group.
- **Comments:** a comment above each class, and above a module constant or function whose purpose is not obvious, says what it does. Inside a body, a comment only explains a non-obvious why.
- **Errors:** an `OSError` of one step (an HTTP error, a timeout, a failed `docker exec`) is a `Failure` and the next step runs; a failed step is exit code `1`; a missing variable is exit code `2`.
- **Every step can run again:** an item is matched by name and replaced, never added twice.
- **Style:** ruff with `E`, `F`, `I`, `UP` and `B`, 4-space indent and lines up to 120; pyright `standard`.
- **Never edit `version.txt` or `CHANGELOG.md`:** the release action owns them.
- **Every change goes through `/supera:ship`:** worktree, pull request, CI green. Nothing is committed to `main` directly and merging is a human action.
